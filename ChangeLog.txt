[04/19/2026]
	Removed the per-race enable panel (US-032): the right-side race-toggle list (the "Enable/Disable variety for races" section) is gone. It was rarely used and cluttered the settings window — the race-variety dict still auto-generates with every humanlike race enabled by default on load, and mod-added races still register via the existing detection path. Players who really need per-race toggling can still set `raceVariety[key].isVarietyEnabled = false` via a save file edit or a config mod, but the in-game UI no longer surfaces it. The settings window's left column now spans full width instead of 54%.
	Asymmetric mood-range sliders (US-031): the "Variety mood impact %" slider is replaced by two direct mood-point sliders — "Max negative variety mood" (default -12, slider -20..0) and "Max positive variety mood" (default +12, slider 0..+20). These are the worst/best mood values the variety thought can produce at its most-barren and most-overwhelming stages; intermediate stages scale linearly toward 0 at the "average menu" stage. Asymmetry is supported: e.g. set -8/+12 to soften penalties while keeping full rewards. Set either to 0 to disable that side entirely. Gourmand trait still doubles the whole range on top. The underlying ThoughtWorker now inspects the pawn's current stage and picks the relevant half-scale instead of applying a single uniform multiplier, so the endpoints mean what they say.
	Direct mood + meal-type bonus tuning (US-030): the "Halve variety mood effect" checkbox is replaced by a continuous "Variety mood impact" slider (0–200%, default 100%). 100% = the mod's previous unchecked-halve baseline (vanilla × 2.0 mood weight); 50% matches the old halve-on behavior; 200% doubles mood swings. The Gourmand trait's × 2 multiplier still stacks on top. A new "Meal Type Bonus" collapsible section exposes the previously-hardcoded bonus step table as five direct integer-percent sliders — one each for 1-slot (simple), 2-slot (fine/lavish), 3-slot, 4-slot, and 5+-slot recipes. Defaults match the former values (0 / 5 / 12 / 20 / 30 %). Set any slot to 0 to disable that tier's bonus entirely, or raise them to boost rotation incentive.
	Save-compat: the old `halveVarietyMoodImpact` boolean stays Scribed for backward compatibility but no longer affects gameplay — players upgrading get mood impact 100% and the default bonus table regardless of their old toggle state. If you previously ran with halve ON, set mood impact to 50% in settings to restore that feel.
	Direct tier tuning (US-029): each expectation tier now has two independently-tunable knobs instead of a single integer multiplied by a hidden factor. "Memory" sets how many past meals that tier averages into mood directly (in meals). "Palate" sets how fresh a meal must be before it counts meaningfully, directly as a percentage (0–50%). Previously the tier integer was silently multiplied by 2.25 to produce the real memory size, and the palate baseline was derived from the same integer via a non-obvious formula — both obscured what the slider actually controlled. The per-tier settings in the Pawn Expectations section now show the exact values gameplay reads. The obsolete "Longer variety memory for pawns" checkbox was removed (its effect is now part of the direct memory settings).
	Tier-change resilience (US-029): per-pawn memory now stores up to max-tier-memory + 6 meals at all times, regardless of the pawn's current tier. Previously a pawn dropping from Noble to Moderate lost 16 meals of history permanently; if they rose back to Noble later, the queue was warm-start-biased until repopulated. Under the new storage cap, tier changes (wealth swings, royal title gain/loss, settings slider edits) never lose history — mood aggregation and meal-def bonus windows shrink to the current tier's memory value while the older meals remain safely archived in storage. Also absorbs the ReCount rebuild warm-up bias (oldest meals scored against zero predecessors) into the archive buffer so visible mood averages only over well-scored meals.
	Save-compat: upgrading from earlier versions uses the new memory/palate defaults (9–34 meals, 4–48% palate) — the legacy `extremelyLowVariety`..`nobleVariety` integers are kept in save files for backward Scribe but no longer drive gameplay. If you had custom tier tuning on an older save, tune again via the preset strip or the Pawn Expectations section.
	Mod Settings redesign (US-028): preset strip on top of the settings window with three difficulty profiles — Easy / Default / Hardcore. Clicking a preset batch-sets the 14 gameplay-affecting knobs (tier values, memory + mood toggles, slave/prisoner percentages) and live-recomputes existing pawn variety mood. The active preset is highlighted; custom tuning shows a "Custom" descriptor. Tooltips on each preset button list the exact values applied. The remaining knobs are grouped into collapsible sections — Basics, Difficulty, Pawn Expectations, Cook Behavior, How Scoring Works — all collapsed by default so a new player sees the preset row first, with section headers beneath for deeper tuning. Expectation tier values now enforce monotonic ordering (Very Low ≥ Extremely Low, and so on) to prevent nonsense sequences. The race list on the right panel is unchanged and remains always-visible. Save-compat: existing saves open without migration; if your prior tuning didn't match any preset, the panel shows "Custom".
	Recalculation coverage expanded: editing any tier value, the minimum-expected-variety floor, the slave/prisoner need toggles and percentages, or the halve-variety-mood / longer-memory toggles now queues a live variety-mood recalculation (previously only the floor and the tier-reset button did). Mid-game setting edits now take effect immediately instead of waiting for the next ingestion.
	Balancing pass: Noble (and other high-expectation tiers) is now reachable without requiring a 100-ingredient pantry. Palate threshold formula softened from (tier − 3)/20 capped 0.9 to (tier − 3)/25 capped 0.50, so the default Noble baseline drops from 0.60 to 0.48. Noble pawns at a moderate 30-ingredient pantry now sit at roughly 40% variety mood (was near zero), 50 ingredients → ~66%, 100 ingredients → ~88%. Perfect-rotation 100% still requires effort (14 unique ingredients cycled through fine meals, or 35 cycled through 5-slot modded recipes). Tier differentiation preserved — Extremely Low remains the easiest, Noble the hardest.
	Meal-type bonus retuned from a linear +5%/ingredient (cap +25%) to a step table keyed on recipe slot count: simple (1-slot) earns nothing, fine/lavish (2-slot) +5%, modded 3/4/5-slot recipes earn +12% / +20% / +30%. The bonus now reflects recipe complexity instead of stuffed-ingredient count, so a simple meal cooked with 3 ingredients still scores as the 1-slot recipe it is. "Capped" tooltip label now fires only when modded 6+ slot recipes are clamped at the max.
	Variety tracking mode simplified: the legacy "by meal names" / "by ingredients" / "by meal names and ingredients" options have been removed. Ingredient Overlap is now the only mode — continuous per-meal scoring based on ingredient overlap with the pawn's last 6 meals, plus a meal-type-new complexity bonus. Existing saves migrate automatically on load (any stored legacy mode name deserializes to the new default). The mode radio buttons are gone from Mod Settings; the palate-memory slider remains. Simpler UI, one coherent behavior to understand.
	Settings window clarity pass: added hover tooltips for seven previously-bare settings (Stack meals by ingredients, Ingredients per meal when cooking, Cook's ingredient-rotation memory, Minimum expected variety, slave/prisoner expected variety %, Halve variety mood effect, Longer variety memory). Slave/prisoner sliders are now clearly labelled as "% of tier" so it's obvious they're multipliers, not raw counts. The expectation-tier explanation now lists both axes it drives (queue size AND palate threshold) with the actual formula. Tracking-mode tooltip rewritten to separate the scoring window (fixed 6 meals) from the memory queue (tier × multiplier) — previously conflated.
	Settings window scroll now sizes to actual content — previous hardcoded 665px content height clipped the scrollbar when conditional rows (slave / prisoner sub-sliders) were on or when tooltips pushed the layout taller. Last rows (Adjustment Factors, race list reset) are now reachable.
	Ingredient Overlap mode: new "Palate memory" slider (0.5-5 days, default 2) in Mod Settings controls how far back a pawn remembers ingredients for overlap scoring. Lower = lenient (only rapid repeats punished), higher = strict.
	Ingredient Overlap tooltip polish: per-meal tooltip now leads with "Variety score: X% (Y of Z ingredients fresh)", lists each ingredient on its own indented line with repeat/new status and pluralized "1 meal / N meals ago" text. Meals with no ingredients (nutrient paste, kibble, raw) use the meal's name as the fallback identifier instead of a hardcoded paste string.
	New variety tracking mode "By Ingredient Overlap": instead of boolean key matching, each meal scores continuously against recent meals — a meal that repeats two of three ingredients counts as ~0.33 variety, while a meal with all-new ingredients counts as 1.0. Meals older than ~2 in-game days fall out of the overlap window. Paste-on-paste correctly scores 0. Select in Mod Settings; existing save trackers rebuild stored scores automatically on load.
	Variety details window (overlap mode): each meal row shows a coloured percentage badge with its per-meal variety score and a hover tooltip breaking the ingredients into "Repeated:" / "New:" sets so you can see exactly why a score came out the way it did. Nutrient paste and other empty-ingredient meals show an explicit "(no ingredients)" fallback. The aggregate panel replaces "Most-repeated meal" / "Most-used ingredient" with "Tired of:" (ingredients eaten twice or more in the decay window) and "Try feeding:" (ingredients that fell out of the window — stale favourites the pawn hasn't revisited). Per-meal status glyph (◆ fresh, ■ repeat, ? forgotten) in the top-left of each meal icon keeps the fresh/repeat distinction readable in grayscale for colourblind accessibility. Age labels ("X minutes/hours/days ago") now pluralize correctly.
	Cook rotation: fixed latent bug where meal-completion records were silently dropped — the Harmony patch targeted the base Bill.Notify_IterationCompleted, but cooking bills are Bill_Production / Bill_ProductionWithUft which override the method, so the postfix never fired and the recent-meals history stopped updating. Patch now targets both concrete types. Combined with the new continuous position-weighted penalty (per-def, newer uses weigh more, older uses fade, fresh-bonus / penalty branches collapse into one continuous term), the cook now rotates through more distinct combinations across meals instead of sticking to one.
	Thread-safety hardening: debounced settings recalculation now defers Verse state mutations (DietTracker.ReCount / UpdateMaxFoodInMemory / VarietyAdjuster.AdjustVarietyLevel) to the main thread via LongEventHandler, preventing races against main-thread readers when a Timer callback fires from the threadpool.
	Food Variety need is now visible on the need list for all pawns; when a pawn is excluded (slaves/prisoners/non-player/trait-opted-out/race-disabled), the tooltip leads with a plain-English reason so the gating is no longer silent.
	Keyed string extraction: settings UI labels, tooltips, tip template, disabled-reason labels, and the three main flavor pools (Forgotten/NoVariety/HasVariety, 20 entries each) now route through RimWorld's Translate() system via Common/Languages/English/Keyed/VarietyMatters.xml. Translators can extend coverage without C# edits.
	Food Variety need tooltip now opens a hover overlay with the tip text plus a row of food icons for what the colonist has eaten recently, surfacing the visual grid VFVE ships as a popup without adding a persistent row to the needs tab.
